# Run V · On-device memory selection for the extension

25 November 2026 · Survey and offline browser benchmark

## v1 decision

Ship the extension with an explicit memory picker and an optional person-chosen profile the person can add to a chat. Leave automatic relevance-based offers and insertion off. On both holdouts, the MiniLM classifier's stricter operating point reached 87.2% precision overall. It reached about 85% in English and missed all six website demo variants. The always-add simulation offered irrelevant context on almost every draft whose labels required no facts. Give the profile a deliberate add control and keep it scoped to ordinary facts the person picked.

For a **manual suggestion pilot**, MiniLM L12 int8 with the two Q2 needs heads on **ONNX Runtime Web WASM** is the reference. It runs without WebGPU in both browsers. Bundle the graph, tokenizer, heads, JS and WASM if the pilot is distributed. The measured Chromium ZIP was 77.2 MiB and the peak process-tree RSS increase was about 821 MiB. That is too heavy to initialize on every chat visit. A person opening the picker can trigger an extension-owned inference document, with a manual list available during loading or after a failure. The small hashed classifier is cheap enough to bundle, with recall too low to be the default picker.

Keep Chrome's Gemini Nano as an opt-in experiment. Chrome manages model availability, download and updates, and the browser here could not provide a session in either language. Q3 found no publicly documented standalone model distribution path. Prefer a shared, versioned CPU path when the user asks for suggestions. Preserve the extension's first-disclosure prompt, fresh consent for sensitive, owner-private or uncertain content, and receipt-before-release for the exact destination and bytes.

### Store distribution and licences

- **Chrome Web Store.** Bundle JS, the WASM runtime, helpers and model-specific kernels. Chrome's hosted-code guidance exempts data from its remotely hosted code definition. Treat a downloaded weight file as a data-only artifact interpreted by the submitted runtime. A model that also downloads a graph with custom operators, model-specific WASM, or executable tokenizer/processor code warrants explicit review. A 2 GB upload ceiling still leaves install, storage and bandwidth costs. [MV3 rules](https://developer.chrome.com/docs/webstore/program-policies/mv3-requirements), [remote hosted code guidance](https://developer.chrome.com/docs/extensions/develop/migrate/remote-hosted-code), [upload limit](https://developer.chrome.com/docs/webstore/publish).
- **Firefox Add-ons.** The maximum upload is 200 MB. AMO requires self-contained operation and disallows remote code execution. A raw weights download is a plausible data case, but the policy gives no model-specific approval. Submit a reproducible build, the exact runtime versions, model provenance and instructions for reviewing first-run network traffic. Recheck the preview policy for submissions on or after 1 December. [AMO policies](https://extensionworkshop.com/documentation/publish/add-on-policies/), [December policy preview](https://extensionworkshop.com/documentation/publish/add-on-policies-preview-2026-12/), [submission limit](https://extensionworkshop.com/documentation/publish/submitting-an-add-on/), [source submission](https://extensionworkshop.com/documentation/publish/source-code-submission/).
- **AGPL.** Apache-2.0 and MIT are OSI-approved and permissive choices for separately identified dependencies in the AGPL-3.0-or-later distribution. Retain licences, notices and applicable change notices, and track upstream weights, conversion scripts and hashes. Gemma 3 and EmbeddingGemma 1 have separate Gemma terms with use and downstream conditions. Llama 3.2 has its own community licence with use, attribution and certain naming and scale conditions. Shipping those weights alongside AGPL code does not relicense the weights. Prefer the permissively licensed candidates for a single Chrome/Firefox distribution, and verify the precise converter and model licences. [OSI Apache-2.0](https://opensource.org/license/apache-2-0), [OSI MIT](https://opensource.org/license/mit), [GNU compatibility](https://www.gnu.org/licenses/license-compatibility.en.html), [Gemma terms](https://gemma.ai/resources/terms/), [Llama 3.2 terms](https://huggingface.co/meta-llama/Llama-3.2-1B-Instruct).
- **Packaging choice.** For v1, bundle the model-free picker and profile. For a suggestions pilot that includes the measured small classifier, bundle pinned data too and load it on demand. If a future model exceeds the shared package budget, first-run download is a separate opt-in with a declared origin and byte count, verified bytes, a retry/offline path, and removal by the owner. Keep all execution artifacts in the submitted package. A download may disclose an IP address to the host, and should carry no wallet facts, draft text, identifiers or telemetry.

## Benchmark design

The original wallet contributes 48 calibration drafts and 152 held-out drafts (76 English and 76 German, 120 relevant picks). The site contributes the exact Lisbon, cover-letter and dinner drafts in both languages. The second wallet contains 40 fresh statements for a fictional Leipzig audio technician and 104 separately phrased drafts, 52 per language, with 86 relevant picks. It includes work and family details, ordinary preferences, protected facts, third-party requests, edits, attempted bulk disclosure, 21 nonblank negative drafts and two literal blanks. The same investigator composed and labelled the second wallet from scratch, with a different person, values and situations. It was frozen by hash before scoring, had no second human annotator, and supplied no examples for training, prompt tuning or threshold selection. The Q2 training generator has zero normalized exact-text overlap with the new drafts and statements. [Wallet](../../spikes/local-model/v/wallet.tsv), [drafts and labels](../../spikes/local-model/v/wallet-drafts.tsv), [fixture checks](../../spikes/local-model/v/test.mjs).

Five combinations completed both holdouts. MiniLM and Granite use a save head and request head trained on Q2’s synthetic statements. EmbeddingGemma 2 tests text-only q4 retrieval against fixed bilingual descriptions of available slots, using the fixture’s slot assignments. Qwen3 tests zero-shot picking directly over the available labelled slots. The WebLLM preflight could not use a hardware adapter, so the scored Qwen3 path uses wllama CPU WASM and Q4_K_M GGUF. That is a different quantization from the MLC build.

The fifth combination keeps confident MiniLM picks and routes only scores within ±0.12 of their Q2 rank floor to Qwen3.5. The reasoner sees that narrow shortlist. Both reasoners see the draft and numbered category descriptions only. A JSON schema and a second strict parser constrain the response to zero to two offered IDs. Generated text and IDs outside the catalogue have no path into the result. The supplemental direct Qwen3.5 trial used the compact taxonomy names, grouping by wallet and language and six CPU threads. The full direct CPU run was stopped after repeated slow attempts. Supplemental short probes use the longer descriptions and four threads. The always-add simulation proposes a fixed, person-chosen pair of ordinary facts from each wallet on every nonblank draft. [Browser runner](../../spikes/local-model/v/browser.mjs), [picker and parser](../../spikes/local-model/v/pick.mjs), [pinned artifacts](../../spikes/local-model/v/weights.mjs).

Precision, recall and F1 count selected entry IDs, micro-averaged. A draft has at most two labels. A false offer on an empty-label draft counts once regardless of the number of wrong picks. Literal blank drafts are also counted separately. Scoring includes protected relevance labels and runs before disclosure policy. Thresholds for new rankers maximize F0.5 on original calibration only, with a second operating point available if each calibration language reaches 90% precision with at least eight selected facts. The v1 decision uses 90% per language on both holdouts and treats roughly 40% recall per language as useful for this spike. Eight calibration picks only qualify a threshold for a trial. Two synthetic wallets and parallel original drafts give limited evidence for generalization.

### Cost and hardware

Chromium 151.0.7922.34 and Firefox 153 ran under Playwright 1.63.0, with a Ryzen 5 5600X and 30 GiB RAM. Each bundle is a synthetic harness archive. Cold measures model initialization after launching a fresh profile and importing the benchmark module, with weights on disk. For the classifiers and MiniLM similarity, index time covers 88 fixture statements across three wallets. EmbeddingGemma 2 builds a single set of 51 slot vectors. Index plus cold is the first time the classifier can pick. Warm p50/p95 use the 262 non-calibration test and demo drafts and include fast abstentions. Peak RAM is a sampled process-tree RSS sum, which can double-count shared pages. The delta uses the loaded page before starting inference. These are single runs under the host's desktop workload. Some long browser runs overlapped and were not isolated for CPU timing. The cascade kept both models resident in one loopback document and its measured latency includes classification and routed generation. Download and archive sizes exclude the actual extension's other features.

## Risks and next decision

- **Coverage and calibration.** Two wallets give a limited view of accuracy across users. The fresh set intentionally has a high rate of positive drafts. Frequent general-purpose chats could lower observed precision. Q2's English and German translations are correlated, the second wallet covers the same taxonomy, and a single investigator labelled its data. Add independently authored and double-reviewed bilingual wallets for confirmation, with a minimum number of picks per language, category-level errors, positives and empty-label offers. Preserve this second wallet as a frozen holdout. Consider a smaller purpose-trained or distilled classifier if it beats the manual-pilot footprint and supports enough recall.
- **Availability and power.** Measure cold, first draft and steady-state performance in a real unpacked extension on Chrome and Firefox with a supported hardware adapter, on low-RAM CPU-only laptops, and on Chrome with a provisioned Nano. Record timestamp-query or device-profiler GPU time, peak dedicated memory, wall time, and power over the same workload. CPU/WASM is the portable test path and manual selection the general fallback.
- **Disclosure boundary.** A valid slot ID is only a relevance suggestion. A model can be steered by a draft, and collision handling can hide relevant facts or choose the wrong entity if save assignments are wrong. Cap offers at two, intersect with the current wallet, reject invalid or uncertain results and require the existing destination, sensitivity, permission, receipt and stale-draft checks. Revalidate those behaviors on the extension-only implementation before enabling any unattended insertion.
- **Distribution.** Larger binary assets increase install, update and storage costs even when model inference is fast. Confirm model and runtime provenance, verify import paths and CSP under the submitted manifests, and validate both stores. Require first-run downloads to succeed separately from wallet and draft processing.
