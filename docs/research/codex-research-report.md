**This is not greenfield.** The broad product already has direct competitors. **AI Passport is the strongest verified counterexample**: encrypted user-controlled memory, progressive category permissions, MCP access, and approval of proposed memories. **Plurality, Vana, Inrupt Charlie, Compartment, and TotalReclaw** cover substantial parts too. [AI Passport](https://ego.ist/trust), [Plurality](https://plurality.network/ai-context-flow/), [Vana](https://vana.org/blog/own-your-ai-memory), [Charlie](https://www.inrupt.com/blog/charlie-the-agent-that-works-for-the-consumer-and-the-bank), [Compartment](https://hermes-agent.nousresearch.com/marketplace/compartment), [TotalReclaw](https://github.com/graphprotocol/totalreclaw).

**I did not verify a product shipping the complete combination:** encrypted user-owned memory, remembered **agent × category × actual model destination** consent, and retained receipts containing the exact disclosed context. The remaining opportunity is that integration and its usability. It is substantially narrower than “portable personal memory.”

There is already infrastructure for implementing receipts:

- OpenClaw’s **`before_model_request`** hook sees final provider-specific payloads and provider/model at the embedded transport boundary, including retries/tool loops/compaction. **5. Standards work is already substantial**

There is no single broadly adopted memory/disclosure standard verified here. There is, however, abundant active prior art:

| Work | Status and relevance |
|---|---|
| **[ApertoMemory](https://datatracker.ietf.org/doc/draft-ferro-apertomemory/)** | Individual experimental Internet-Draft; encrypted signed portable memory, Python/TS/MCP implementations. Not IETF-endorsed. |
| **[Memory Projection Records](https://datatracker.ietf.org/doc/html/draft-ferro-schrock-memory-projection-record-01)** | Individual draft, Aug 2026. Exact emitted context commitments and bounded reciprocal implementation evidence. Explicitly does not establish model receipt/use or action outcomes. |
| **[SAIHM](https://datatracker.ietf.org/doc/draft-saihm-memory-protocol/)** | Individual memory protocol draft. Current revision specifies **custodial** operation with operator-held keys; weaker fit to your custody requirement. Not an RFC. |
| **[Memory Interchange Bundle](https://datatracker.ietf.org/doc/draft-vu-aimem-bundle/)** | Individual export/import format draft; relevant portability work, not an adopted format. |
| **[PCP](https://pcp-protocol.github.io/pcp/SPEC.html)** | Independent pre-1.0 MCP memory/profile/consent/export specification with conformance suite. |
| **[UMP](https://github.com/edihasaj/universal-memory-protocol)** | Independent protocol calling its version 1.0 stable; **34 stars**, active Oct 2026. JSON/Markdown, provenance, capabilities, MCP/HTTP/file bindings. Audit remains server-local/non-normative. Spec Apache-2.0; package MIT. |
| **[UOMP](https://www.uomp.org/en/spec/)** | Independent session-based memory-consent protocol/reference runtime. Scope, duration, revocation and local audit; no standardized retained disclosure content. |
| **[memorywire](https://github.com/mthamil107/memorywire)** | Independent wire format/reference implementation and human write-review channel. Deeper MCP extension is a proposal. |
| **[W3C AI Agent Memory Interoperability CG](https://www.w3.org/community/ai-agent-memory-interop/)** | Charter v1.1 adopted **23 Nov 2026**. Community Group work; **not W3C Recommendations or standards**. |
| **[MCP memory proposals](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/2342)** | MIF proposal closed March 2026; another [memory-extension issue](https://github.com/modelcontextprotocol/modelcontextprotocol/issues/3564) closed Nov 20 and routed toward working-group discussion. Neither is an accepted memory extension. |
| **[AAIF](https://aaif.io/projects)** | Hosts major agent interoperability work; no listed memory protocol verified. Its [security/privacy WG](https://github.com/aaif/wg-security-and-privacy/blob/main/charter/charter.md) covers memory vulnerabilities. |
| **[DIF Trusted AI Agents](https://identity.foundation/working-groups/trusted-agents.html)** | Active identity/delegation/governance work. No comparable memory-disclosure format verified. |
| **[FIDO agent work](https://fidoalliance.org/fido-alliance-to-develop-standards-for-trusted-ai-agent-interactions/)** | Announced April 2026 around trusted agent interactions and payments, including AP2 contributions. Not a memory standard. |

Additional receipt/delegation drafts deserve tracking:

- **Agent Decision Commitments** binds payment decisions to exact model-input context commitments and supports selective disclosure. [Draft](https://datatracker.ietf.org/doc/draft-milan-agent-decision-commitment/)
- **Acta signed decision receipts** records tool access-control decisions, policy and evidence; updated **21 Nov 2026**. [Draft](https://datatracker.ietf.org/doc/draft-farley-acta-signed-receipts/)
- **OSAP consent receipts**, published in November, binds task, agent, audience, actions/resources and validity, with an ISO 27560 mapping. [Draft](https://www.ietf.org/ietf-ftp/internet-drafts/draft-zeng-osap-consent-receipts-00.html)
- **SADP delegation** addresses capability chains and encrypted scoped context references. [Draft](https://datatracker.ietf.org/doc/draft-atakora-wimse-sadp-delegation/)
- **MyTerms MCNP** has a November wire-protocol draft, separate from published IEEE 7012. [Draft](https://datatracker.ietf.org/doc/draft-curtis-myterms/)

These are **individual Internet-Drafts**, not adopted IETF standards, regardless of document headers.

Research also predates the proposed combination: **Wu et al.’s Agent-Memory Protocol** formalizes redact-at-rest, purpose-specific packing and local hydration; **SP-Mem** implements consent-sensitive retrieval of protected exact values. Neither establishes a complete shipped consumer product. [AMP, January 2026](https://proceedings.mlr.press/v317/wu26a.html), [SP-Mem](https://arxiv.org/abs/2608.16551).

**7. The single biggest threat over the next twelve months**

**Egoist AI Passport closing the remaining disclosure-accountability gap.**

It already ships most of the difficult product loop: category-specific cryptographic access, remembered permissions, MCP access, an owner approval inbox, and app/category/purpose/duration grants. It also documents **directed disclosure to an exact HTTPS destination**, with owner approval and signed attestations—currently separate from ordinary memory passes. [Memory permissions](https://ego.ist/docs/agents), [encryption/proposals](https://ego.ist/trust), [directed disclosure](https://ego.ist/docs/directed-disclosure).

My inference is that extending those mechanisms into a retained disclosure history and stronger model-destination binding is a plausible incremental product expansion. Its **$3M seed and public launch** make this a concrete competitive threat. [Funding](https://www.globenewswire.com/fr/news-release/2026/10/07/3376549/0/en/egoist-machines-ai-passport-goes-live-today-only-way-to-make-your-personal-context-portable-across-ai-assistants-like-chatgpt-claude-muse-and-gemini-but-still-owned-by-you.html)

**The defensible proposition is narrower:** an open-source, independently synced personal-memory store whose permissions remain valid across agents and whose receipts preserve exactly what crossed a verified model-provider boundary. The broad “own your memory and connect any agent” proposition already exists.
